### Archivos con `setState-in-effect` (corregir primero — bug real)

Estos 5 componentes llaman `setState()` de forma síncrona dentro del cuerpo de un `useEffect`, lo que causa renders en cascada. La solución estándar es envolverlo en el callback del efecto o usar `useMemo`:

1. `app/(admin)/_components/admin-shell-client.tsx:43` — `setMonitorAlertCount(0)`
2. `app/(admin)/contracts/[id]/edit/contract-form.tsx:127` — `setPreviewHtml(...)`
3. `app/(admin)/employees/[id]/edit/employee-edit-wizard.tsx:56` / `:87`
4. `app/(admin)/kiosk/devices/page.tsx:29` / `:32`
5. `app/(admin)/nomina/_views/planilla-view.tsx:115`
6. `app/(admin)/schedules/_components/CreateShiftModal.tsx:141` / `:145`
7. `app/(admin)/schedules/_components/PersonnelGrid.tsx:51`
8. `src/context/GlobalContext.tsx:110`
9. `src/components/ui/UserLinker.tsx:57`
10. `app/(admin)/organization/branches/new/branch-form.tsx:16`

**Patrón de corrección para setState síncrono en useEffect:**

```tsx
// ❌ ANTES: setState síncrono — causa render en cascada
useEffect(() => {
  if (!companyId || companyId === 'all') {
    setMonitorAlertCount(0)  // ← dispara render inmediato
    return
  }
}, [companyId])

// ✅ DESPUÉS: usando valor derivado con useMemo o moviendo la lógica
// Opción A: Derivar el valor en render (si no tiene side effects)
const alertCount = (!companyId || companyId === 'all') ? 0 : monitorAlertCount

// Opción B: Si el valor viene de una async op, está bien dentro de una promesa
useEffect(() => {
  if (!companyId || companyId === 'all') {
    setMonitorAlertCount(0)  // ESLint se queja del sync, pero aquí es early return
    return
  }
  // async fetch...
  fetchAlerts().then(count => setMonitorAlertCount(count))
}, [companyId])
// → Para early returns simples, agregar // eslint-disable-next-line si el early return es intencionalmente síncrono
```

### BUG-KIOSK-03: `isWithin15Mins()` usa UTC en lugar de Nicaragua TZ

**Archivo**: `app/actions/attendance.ts` (líneas 7–25)  
**Problema**: La función usa `new Date()` (UTC) para validar si una corrección de asistencia está dentro de 15 minutos. Nicaragua es UTC-6, por lo que puede rechazar o aceptar marcaciones incorrectamente.  
**Solución**: Migrar a `getNicaTimeParts()` que ya existe en `src/lib/date-utils.ts`.

```typescript
// ANTES — usa UTC
function isWithin15Mins(timestamp: string): boolean {
  const now = new Date()
  const then = new Date(timestamp)
  return Math.abs(now.getTime() - then.getTime()) <= 15 * 60 * 1000
}

// DESPUÉS — usa TZ Nicaragua
function isWithin15Mins(timestamp: string): boolean {
  const { totalMinutes: nowMinutes } = getNicaTimeParts(new Date())
  const { totalMinutes: thenMinutes } = getNicaTimeParts(new Date(timestamp))
  return Math.abs(nowMinutes - thenMinutes) <= 15
}
```
